## 三、改造要点详解

### 3.1 Delete 键改造

**旧逻辑的问题：**

```csharp
// ❌ 旧：直接隐藏物体，不通知 Manager
private void DeleteOrHideSelectedObject()
{
    obj.SetActive(false);
    resetobjs.Push(obj);           // 自己存 Stack
    selectedobjs.Clear();
    // FacilityManager 不知道这件事！
}
```

**新逻辑的原理：**

```
按 Delete 键
  → 遍历 selectedobjs
  → 对每个物体：取 FacilityIdentity.Id
  → 调用 FacilityManager.Instance.DeleteFacility(id)
  → Manager 负责：改数据、存档、广播事件
  → 事件处理函数 OnFacilityDeletedHandler 自动处理：隐藏、清高亮、移出列表
```

新逻辑中 `DeleteOrHideSelectedObject()` 改成：

```csharp
private void DeleteOrHideSelectedObject()
{
    if (selectedobjs.Count == 0) return;

    // 遍历选中列表，取 ID 调用 Manager
    for (int i = selectedobjs.Count - 1; i >= 0; i--)
    {
        GameObject obj = selectedobjs[i];
        if (obj == null) continue;

        FacilityIdentity identity = obj.GetComponent<FacilityIdentity>();
        if (identity != null)
        {
            FacilityManager.Instance.DeleteFacility(identity.Id);
            // 剩下的事由 OnFacilityDeletedHandler 自动处理
        }
    }
    // selectedobjs.Clear() 不再需要手动调用
    // 事件处理函数中已经逐个移除了
}
```

### 3.2 R 键改造

**旧逻辑：**

```csharp
// ❌ 旧：从自己的 Stack 恢复，不改数据
if (Input.GetKeyDown(KeyCode.R))
{
    GameObject obj = resetobjs.Pop();
    obj.SetActive(true);
}
```

**新逻辑的原理：**

```
按 R 键
  → 调用 FacilityManager.Instance.GetRecentDeletedFacilityId()
  → 拿到 ID 后调用 FacilityManager.Instance.RestoreFacility(id)
  → Manager 负责：改数据、存档、广播事件
  → 事件处理函数 OnFacilityRestoredHandler 自动处理：显示物体、重新高亮
```

```csharp
if (Input.GetKeyDown(KeyCode.R))
{
    string id = FacilityManager.Instance.GetRecentDeletedFacilityId();
    if (id != null)
    {
        FacilityManager.Instance.RestoreFacility(id);
        // 剩下的事由 OnFacilityRestoredHandler 自动处理
    }
    else
    {
        Debug.Log("没有已删除的设施可恢复");
    }
}
```

### 3.3 hiddenObjects 字典的作用

**为什么需要它？**

- 删除时：物体 `SetActive(false)` 后射线检测不到，但它的 `FacilityIdentity` 组件还在
- 恢复时：需要根据 ID 找到对应 GameObject，调用 `SetActive(true)`
- 用 `Dictionary<string, GameObject>` 存 ID → GameObject 的映射，恢复时直接查

```csharp
// 删除时存入
hiddenObjects[id] = obj;

// 恢复时取出
if (hiddenObjects.TryGetValue(id, out GameObject obj))
{
    obj.SetActive(true);
    hiddenObjects.Remove(id);
}
```

### 3.4 事件处理函数完整逻辑

```csharp
private void OnFacilityDeletedHandler(string id)
{
    // 1. 在选中列表中查找对应物体
    GameObject obj = selectedobjs.Find(o =>
        o.GetComponent<FacilityIdentity>()?.Id == id);
    if (obj != null)
    {
        // 2. 存入 hiddenObjects 供恢复用
        hiddenObjects[id] = obj;
        // 3. 隐藏物体
        obj.SetActive(false);
        // 4. 移除高亮
        HighlightSystem2.Instance.RemoveHighlight(obj);
        // 5. 移出选中列表
        selectedobjs.Remove(obj);
    }
}

private void OnFacilityRestoredHandler(string id)
{
    // 1. 从 hiddenObjects 找到被隐藏的物体
    if (hiddenObjects.TryGetValue(id, out GameObject obj))
    {
        // 2. 显示物体
        obj.SetActive(true);
        // 3. 重新高亮
        HighlightSystem2.Instance.EnableHightlight(obj,
            Color.Lerp(Color.red, Color.yellow, 0.5f), 10f);
        // 4. 重新加入选中列表
        selectedobjs.Add(obj);
        // 5. 从 hiddenObjects 移除
        hiddenObjects.Remove(id);
    }
}
```

## 四、常见问题

### Q1：如果删除时物体没有 FacilityIdentity 组件怎么办？

目前方案假设所有 Pipe 都有 `FacilityIdentity`。如果没有，`GetComponent<FacilityIdentity>()` 返回 null，跳过不处理。可以在 `DeleteOrHideSelectedObject` 中加入警告日志：

```csharp
if (identity == null)
{
    Debug.LogWarning($"物体 {obj.name} 没有 FacilityIdentity 组件，跳过");
    continue;
}
```

### Q2：R 键恢复的「最近删除」是按什么排序？

按 `FacilityData.addedTime` 字符串排序（格式 `"yyyy-MM-dd HH:mm:ss"`），字母序和实际时间顺序一致。

### Q3：选中物体后如果场景重载，selectedobjs 丢失怎么办？

这是正常的。`selectedobjs` 是运行时列表，重载后重新初始化。但 JSON 数据不会丢——删除状态以 `isDeleted` 为准。

### Q4：旧代码的 resetobjs Stack 为什么要移除？

避免两套逻辑打架。删除的状态以 JSON 和 `hiddenObjects` 为准，`resetobjs` 是旧方案遗留，和新的 Manager 事件体系冲突。
